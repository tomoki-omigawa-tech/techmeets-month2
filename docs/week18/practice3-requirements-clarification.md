# 練習課題3：曖昧な要求を明確な要件に整理する

練習課題1のヒアリングで「ベーカリー麦の穂」から出た曖昧な要望を、確認の質問を通して、実装とテストができる要件に整理する。

## 整理のポイント
- **数値にする**：「速い」「たくさん」を秒数・件数に置き換える
- **目的に立ち返る**：「なぜそれが必要か」を聞き、本当の課題を見つける
- **誰が・いつ・どこで**を決める：利用者・タイミング・端末をはっきりさせる
- **テストできるか**で判断する：「できた／できていない」を判定できる形にする
- **スコープを判断する**：今回やるか、フェーズ2に回すかを決める

## 詳細例：No.5「売れ残りを減らしたい」
最初は「値引き機能がほしい」という意味かと考えたが、目的を深掘りすると課題は次のとおりだった。

1. 「今は製造数をどう決めていますか？」→ 前日の夕方に、勘で決めている
2. 「予約の数が前日に分かれば役に立ちますか？」→ それが分かれば作りすぎが減る
3. 結論：本当に必要なのは値引きではなく「前日のうちに予約数が確定し、集計されること」

このように、要望をそのまま機能にせず「なぜ必要か」を確認することで、より効果の高い要件にできる。値引き（タイムセール）機能は Could としてフェーズ2で検討する。
